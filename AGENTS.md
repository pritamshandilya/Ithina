# OpenCode / AI Agent Instructions

This repository is a React + Vite + TypeScript frontend. It has strict architectural constraints and uses several modern/non-standard tools (like the native Node test runner and Tailwind v4).

## 1. Architecture & Boundaries (`STRUCTURE.md` is Law)
- **Strict Layering**: `routes` → `components`/`hooks` → `queries`/`lib` → `models`/`types`.
- **No API in UI**: Components and Routes must NEVER call `axiosClient` or `fetch` directly. All API logic must reside in `src/queries/*`.
- **Domain-Driven Grouping**: Code is organized by domain (e.g., `src/queries/analysis`, `src/routes/analysis`). Keep feature code together instead of grouping broadly by type.
- **Routing**: `@tanstack/react-router` (file-based). `src/routeTree.gen.ts` is auto-generated by the Vite plugin. Do not edit it manually.

## 2. API & Role Rules (`FRONTEND_ROLE_ENDPOINTS.md`)
- **API Client**: Always use `axiosClient` from `@/lib/api/axios-client`. It handles token injection and standardizes `ApiError`.
- **Roles**: Only `admin`, `maker`, and `checker` exist.
- **Store Scope**: Store-scoped endpoints require an `X-Store-Id` header (UUID), **NOT** path params like `/{store_id}`. `axiosClient` and query hooks handle passing this using the Redux store (`selectSelectedStore`).
- **State Management**: `@tanstack/react-query` for all server state. `@reduxjs/toolkit` for global client state (only for UI/workflow state, not cached server data).

## 3. Workflow & Commands
- **Package Manager**: Use **`pnpm`** (specifically v10.x). NEVER use `npm` or `yarn`.
- **Testing (Gotcha!)**: We use the **Node.js native test runner** with `tsx`, NOT Vitest or Jest.
  - Run all tests: `pnpm test`
  - Run a single test (exact command needed due to pnpm symlink structure):
    ```bash
    node --import ./node_modules/.pnpm/tsx@*/node_modules/tsx/dist/loader.mjs --test test/<filename>.test.ts
    ```
- **Lint & Format**: `pnpm lint:check`, `pnpm format`

## 4. UI & Styling (Tailwind v4)
- **Tailwind v4 (Gotcha!)**: This project uses Tailwind CSS v4 via `@tailwindcss/vite`. It is imported via `src/global.css`. There is **no** `tailwind.config.js`. Do not try to create or edit a Tailwind config file, and be mindful of v4 vs v3 syntax differences.
- **Components**: `shadcn-ui` is used (configured in `components.json`). Primitives belong in `src/components/ui/`.
- **Icons**: Use `lucide-react`.
